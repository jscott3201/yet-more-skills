# Optional lane note

Use only when parallel work needs a written handoff. Keep it in the existing task note rather than creating a new tracking system.

| Lane | Outcome | Owned area | Shared dependency | Evidence |
| --- | --- | --- | --- | --- |
| First lane | One useful result | Relevant paths or components | Contract owned by the integrator, if any | Actual checks and remaining gaps |
| Second lane | Independent useful result | Relevant paths or components | State the dependency rather than guessing it | Actual checks and remaining gaps |

Name the integration owner and the combined behavior to test. Ordinary branches or PR links are enough context. Update the note only when a real dependency or outcome changes. It is not an admission packet, immutable allowlist, approval record, or reason to reject a routine authorized integration fix.
