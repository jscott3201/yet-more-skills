# Focused review prompts

**Identity:** Can an old response, handle, or deadline token affect a new occupant after reuse? Is cleanup checked against the same identity as completion?

**Ownership:** Can the borrowed data outlive its owner? Can a small result retain an unexpectedly large frame? Is shared mutation introduced only to bypass a borrowing difficulty?

**Failure atomicity:** After a partial encode, failed sync, cancelled await, or rejected mutation, which state is visible? Does the API promise match that state?

**Validation scope:** Did the changed crate's tests run, or only a cheap subset? Did default filters, required features, or workspace exclusions hide the target? Were doctests or Python tests assumed rather than executed?

**Reference independence:** Was the expected output derived independently, or simply emitted by the changed engine? Is a shared mathematical kernel an acknowledged limit on independence?

**Numerical meaning:** Were exact integers converted through floats? Did summation order, signed zero, NaN handling, or score direction change? Is an alleged tolerance actually in the product contract?

**Performance:** Did the benchmark remove setup or errors that production still pays? Did lower quality, relaxed durability, larger caches, or a smaller offered load buy the apparent improvement?

Apply these prompts to the actual changed boundary and repository policy; they are not a universal lint checklist.
